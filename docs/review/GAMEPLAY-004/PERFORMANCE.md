# Performance and resource evidence

Measurement scripts: `collectible-audit.mjs` (Node24.11.1), `collectible-browser.mjs` (local headless Chrome156.0.8078.80). Full raw samples are packaged; timings vary across runs. The precommit samples below were collected while other regression work was active and must not be treated as device FPS targets.

Six1500m model runs: 43,626 fixed steps,78 admitted sections,63 ordinary sections,28 fragments (peak active1, hard capacity8). Thirty opportunities include two skipped placements (6.67%);49 candidate points rejected. No second beam search or additional trajectory work is run for fragments. Every original admitted hazard witness independently replays; counterfactual tests confirm identical obstacle publication and witness hashes under identical inputs with rewards disabled. Across these different histories, admitted ordinary-section rate is .533–.800/100m; differing player inputs also change hazard admission. This is not a claim that rewards alter generator density.

Node per-step update p50 .0003–.0013ms, p95 .0039–.0065ms in the quoted precommit sample. Occasional scheduler/GC/OS outliers up to16.84ms were observed in the timed region. Eight-active-fragment sweep stress:200 batches ×1000 updates, p50 .00143ms/update, p95 .00895ms/update, worst batch average .15169ms/update. These numbers include slot iteration and swept queries. Placement warm medians .015–.038ms/admitted section, maxima .14–.42ms in later runs; the initial cold sample was5.83ms. Timing instrumentation is outside production code. The earlier locale-dependent sort was replaced by explicit code-point order to remove locale dependence and cold collation setup.

One visible fragment adds exactly3 draw calls (crystal/core/halo); the brief burst adds1. In the same frozen scene the paired renderer samples compare33 calls without fragment rendering and36 with it. World.render CPU submission time, GPU resource counts and native real-time frame intervals are recorded in browser JSON. They are not GPU-completion times. Real-time recordings under concurrent headless regression load had median frame intervals about45–64ms and p95 about118–163ms; this environment did **not** demonstrate60FPS. Use isolated paired samples in the final raw log to assess overhead, and physical devices before making an FPS claim. No general renderer or planner performance claim is made.

Resources: three new shared geometries, four materials, zero textures, fixed8 fragment groups +1 burst mesh. Twenty browser restarts at the same real275m flight state retain exactly30 geometries/1 existing texture; no GPU count growth. Raw heap samples oscillate with garbage collection rather than offering a retained-heap bound. Fifty Node resets retain8 slots; fresh-GC precommit heap16898712→16716120 bytes, ArrayBuffers528715→38843 bytes. Finite measurements and exact disposal event tests are evidence, not an indefinite leak proof.

Existing static GLB collision audit and Phase2 release audit are run separately. Full typecheck, tests, build and browser outcomes are recorded with exit codes in the ZIP. Vite's existing >500kB chunk advisory remains. No dependencies, production texture assets, post-processing, director budgets or movement constants were added/changed.
